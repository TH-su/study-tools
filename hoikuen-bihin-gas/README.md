# 保育園 物品管理台帳 — サーバー（Google Apps Script）

`hoikuen-bihin.html` を複数の端末で同じ台帳として使うためのサーバー。GAS の Web アプリ（`Code.js`）。

## 公開範囲（セキュリティの判断）

- 実行するユーザー: 自分（所有者）／アクセスできるユーザー: 全員（Google ログイン不要）
- 理由: 使うのは別法人の保育園の職員で、この Google Workspace のアカウントを持たない。「Google ログイン必須」にしても園の区別はできず、「アクセスしているユーザーとして実行」にするとスプレッドシート自体を共有することになり、全園の行が見えてしまう。
- そのため URL だけでは何もできない作りにした。すべての操作にこのアプリのログイン（メール＋パスワード → 30日のセッション）を求め、サーバーの中で「その人が所属する園」のスプレッドシートと写真フォルダだけを開く。パスワードは塩つきで3000回ハッシュしてから保存し、セッションと招待コードはハッシュだけを保存する。ログインとコードの入力は、10回続けて間違えると15分止まる。

## 保存場所

マイドライブ直下のフォルダ「保育園物品管理台帳_サーバーデータ（別法人用）」（介護の業務データとは別）。
- 管理用スプレッドシート: 園・利用者・所属・セッション・招待コード
- 園ごとのフォルダ: その園の台帳スプレッドシート（品目・個体・記録・棚卸・設定・写真の表）と写真フォルダ。どれも共有しない（所有者だけ）

## 同期の規則（~/.claude/rules/multi-device-sync.md）

- 正本はサーバー。端末の IndexedDB は園と利用者ごとの控え（`hbsync_<園>_<利用者>`）と送信待ち。
- 書き込みは `apply` だけ。1回の保存＝1つのまとまり（batch）で、同じ batch は2回目以降は何もしない（通信が切れて送り直しても在庫が二重に増えない）。
  - `set`: 変えた項目だけ。`checks`（棚卸の確認）と `photoLabels` は1段深く足し合わせる
  - `inc`: 消耗品の在庫は増減で送る
  - `arr`: 写真の並び・選択肢の一覧は「足した物・外した物・並び順」で送る（他の端末が足した物は残る）
  - 削除は消した印（データは残る）。消した物を他の端末が直した時は、消すより残す方に倒して戻す
  - `create`: 前の版の端末データの移行で使う。サーバーに一度も無かった物だけを足す（意図して消した物は戻さない）
- 変更には園ごとの通し番号（rev）をサーバーが振る。すべて書き終えてから番号を公開するので、取り込みは「前回の番号より後」だけで漏れない。

## アカウントの発行

1. 運営者が園を作る（運営者キーは手元の `~/.claude/knowledge/hoikuen-bihin-op-key.txt`、コードにはハッシュだけ）:
   `{"action":"op","key":"…","op":"createOrg","name":"〇〇保育園","adminEmail":"管理者のメール"}` を POST → 初回の管理者用コード（7日・1回）
2. 管理者は台帳の「招待コード・再設定コードをお持ちの方」から、メール・コード・自分で決めたパスワードで始める。
3. 以降は管理者が「設定 → メンバー」で職員に招待コード（7日）・再設定コード（1日）を出す。再設定コードは使う時点でも「その園の職員で、ほかの園に属していない」を確かめ直す。
4. 運営者の復旧用: `op: "issueReset"`（本人以外が先に登録したメールアドレスなどの救済）。
