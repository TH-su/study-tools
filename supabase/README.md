# 保育園 物品管理台帳 — サーバー（Supabase）

`hoikuen-bihin.html` が複数の端末で同じ台帳を使うためのサーバー側の定義。介護の本番（care-log）とは別のプロジェクト。

## 仕組み

- **正本はサーバー**。端末の IndexedDB は「控え（キャッシュ）＋送信待ち」。園と利用者ごとに別の控え（`hbsync_<園>_<利用者>`）を持つ。
- 表は `items` `assets` `logs` `stocktakes` `settings` `photos`。どれも `(org_id, id)` を鍵に、中身を `data`（JSON）で持つ。`id` は端末で振った値をそのまま使うので、同じ物を2回送っても二重にならない。
- **書き込みは `hb_apply(org, batch, ops)` だけ**。1回の保存＝1つのまとまり（batch）で、同じ batch は2回目以降は何もしない（通信が切れて結果が届かず送り直しても、在庫が二重に増えない）。
  - `set`: 変えた項目だけを書く。送っていない項目はサーバーの値のまま。`checks`（棚卸の確認）と `photoLabels` は1段深く足し合わせる。
  - `inc`: 消耗品の在庫は増減の差分で送る（2台で同時に入庫・使用しても打ち消し合わない）。
  - `arr`: 写真の並び・選択肢の一覧は「足した物・外した物」で送る。
  - 削除は `deleted = true`（消した印）。データは残る。印の付いた物を別の端末が直した時は、消すより残す方に倒して元に戻す。
- 差分を取り出すための時刻（`updated_at`）はサーバーが付ける（端末の時計は使わない）。
- 写真・PDF は非公開の Storage バケット `hb-photos` の `<園のid>/<写真のid>` に置き、署名付きURLで取り出す。

## 園ごとの分離（RLS）

- どの表も「自分が所属する園の行」しか読めない・書けない（`hb_private.is_member`）。
- 所属（`memberships`）は利用者からは書けない。招待コード・管理者の操作（関数）だけが変える。
- Storage も最初のフォルダ名＝自分の園のidの時だけ読める・書ける。

## アカウントの発行

1. 運営者が園を作る（SQL を postgres で実行）:
   `select hb_private.create_org('〇〇保育園', '管理者のメールアドレス');` → 初回の管理者用コードが返る（7日間有効・1回だけ）
2. 管理者はアプリの「招待コード・再設定コード」から、メール・コード・自分で決めたパスワードを入れて始める（Edge Function `hb-invite`）。
3. 以降、管理者はアプリの「設定 → メンバー」で職員のメールアドレスに招待コードを出す。パスワードを忘れた職員には再設定コード（1日有効）を出す。
   コードは保存せず sha256 だけを持つ。間違いが10回続いたコードは使えなくなる。

パスワードは本人しか知らない（管理者にも運営者にも見えない）。メールの送信は使わない。
